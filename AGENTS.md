# Алгоритм работы ИИ с Danil Portfolio

## Цель проекта

Поддерживать личное портфолио Python backend-разработчика: один сайт с проектами, опытом, навыками и контактами. Рабочий язык — русский. Сайт статический, без сборки и серверной части.

## Источники фактов

- Опыт, даты и контакты: `docs/PROFILE.md`, записанные со слов владельца.
- Возможности проектов: README соответствующих репозиториев `https://github.com/dil2324`.
- Тексты и ссылки сайта: `index.html`, массив `projects` в `app.js`.
- Не придумывать работодателей, фамилию, метрики, отзывы, количество пользователей или уровень владения технологиями.
- При противоречии с резюме уточнить конкретный факт у владельца. Недоступность hh.ru не означает отсутствие опыта.

## Порядок работы

1. Прочитать задачу, этот файл и `README.md`. Проверить структуру проекта и, если репозиторий инициализирован, `git status --short`. Сохранить чужие незакоммиченные изменения.
2. Найти нужные файлы через `rg` или `rg --files`. Не читать все файлы и не запускать повторно выполненные проверки без причины.
3. Определить проверяемый результат: что пользователь увидит после правки. Для небольшой задачи сразу перейти к реализации; для крупной кратко обозначить шаги.
4. Менять минимально необходимый набор файлов. Сохранять текущий стек HTML/CSS/JavaScript; фреймворк и зависимости добавлять только при реальной необходимости.
5. Сверять тексты с источниками. Визуальные макеты обозначать как иллюстрации. Не выдавать макет за скриншот, а ссылку из README — за проверенный работающий сервис.
6. Проверить результат согласно разделу ниже. Исправить обнаруженные ошибки.
7. Обновить документацию, если изменились запуск, структура, источники данных или публикация.
8. Дать короткий отчёт: что изменено, как посмотреть, какие проверки выполнены и что осталось недоступно. Публикацию подтверждать только после успешного развёртывания.

## Проверки

- Для JavaScript выполнить `node --check app.js`.
- Для изменений поведения или вёрстки открыть сайт локально и проверить компьютер и телефон, включая ширину 320 px.
- Проверить отсутствие горизонтальной прокрутки и ошибок JavaScript.
- Проверить фильтры, открытие и закрытие карточек, Escape, клавиатурный фокус, мобильное меню и обе темы.
- Проверить ссылки и доступность изменённых локальных файлов. Внешние сервисы проверять отдельно, с ограничением времени ожидания.
- Для полной проверки интерфейса доступен `node scripts/check-browser.mjs`. Нужны Node.js 22+ и установленный Chrome. Снимки и отчёт сохраняются в `artifacts/`.
- Не писать тесты ради повторения реализации. Небольшие изменения текста проверять чтением итогового файла.

## Совместная работа агентов

Использовать подагентов, когда пользователь поручил параллельную работу и есть независимые подзадачи. Сам этот файл не запускает агентов и не настраивает их доступ.

- Основной агент определяет задачу, распределяет файлы, объединяет результат и проверяет сайт целиком.
- Агент интерфейса работает с `styles.css`; изменение структуры согласует с основным агентом.
- Агент контента проверяет `docs/PROFILE.md` и тексты, отдаёт замечания либо меняет только заранее назначенный файл.
- Агент проверки читает код и тестирует браузер, возвращает воспроизведение ошибки; не меняет файлы без назначения.
- До запуска каждому задать входные данные, разрешённые файлы и ожидаемый результат.
- Не поручать двум агентам одновременное редактирование одного файла. Зависимые задачи выполнять последовательно.
- Небольшую правку делать одним агентом. Соблюдать фактический лимит среды; наличие нескольких агентов не гарантирует ускорение.

## Границы действий

Локальные обратимые правки и проверки выполнять в рамках задачи без лишних согласований. Соблюдать уже выданное пользователем разрешение на публикацию. Если публикация не входит в поручение, сначала подготовить проверяемый сайт, затем уточнить размещение. Не отправлять сообщения работодателям, не раскрывать секреты и не изменять другие репозитории без соответствующего поручения. Не заявлять, что сайт опубликован, если создан только локальный файл.
